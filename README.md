# Vending Machine

Виртуальный аппарат по продаже напитков по [техническому заданию](description.md). Один и тот же аппарат работает в браузере и в консоли. Под ним свой мини-фреймворк без зависимостей: автозагрузка PSR-4, контейнер с автосборкой через Reflection, роутер, шаблоны, хранилища и консольные команды.

Нужен PHP 7.1+ с расширениями json и mbstring.

## Запуск в браузере

```bash
php -S localhost:8000 index.php
```

Открыть http://localhost:8000. На Apache запросы направляет в `index.php` файл `.htaccess`, приложение работает и из подкаталога. Состояние аппарата хранится в сессии, у каждого посетителя свой кошелек.

## Запуск в консоли

```bash
php bin/vending status        # напитки, кошелек и монеты аппарата
php bin/vending insert 10 10  # внести монеты
php bin/vending buy 2         # купить напиток по номеру
php bin/vending refund        # вернуть внесенную сумму
php bin/vending reset         # начальные данные
php bin/vending shell         # интерактивный режим
```

```
$ php bin/vending insert 10 10 5
Внесено: 25 руб.
$ php bin/vending buy 1
Ваш напиток: Чай за 13 руб.
Сдача: 10 руб. x 1, 2 руб. x 1 = 12 руб.
```

Состояние консольной версии лежит в `storage/cli.json`. Команда, которая закончилась ошибкой, ничего не сохраняет: если в `insert 10 3` монеты по 3 руб. нет, десятка тоже остается в кошельке.

## Как устроено

```
index.php, bin/vending   точки входа: роуты и консольные команды
config.php               пути и алгоритм сдачи
data/                    начальные данные: кошелек, монеты аппарата, напитки
templates/               шаблоны страниц
src/Framework/           мини-фреймворк: Container, Http, View, Storage, Console
src/Vending/             аппарат без привязки к вебу и консоли
src/App/                 контроллер и консольные команды поверх Vending
tests/                   тесты подбора сдачи и покупки
```

- `Coins` - неизменяемый набор монет "номинал => количество", вся арифметика с монетами только через него.
- `Machine` - аппарат: принимает монеты, продает напиток, возвращает сдачу. Если сдачу выдать нельзя, покупка отменяется, внесенная сумма остается.
- `Simulation` - покупатель с кошельком у аппарата.
- `SimulationRepository` - сохраняет и восстанавливает состояние через любое хранилище: сессию в вебе, JSON-файл в консоли.

## Сдача

Алгоритм выбирается в `config.php`:

- `optimal` (по умолчанию) - динамическое программирование по суммам с учетом того, сколько монет каждого номинала осталось в аппарате. Находит наименьшее число монет или сообщает, что сдачу набрать нельзя.
- `greedy` - сначала самые крупные монеты. Для номиналов 1, 2, 5 и 10 при полном запасе дает тот же результат, но может не найти сдачу, когда монет мало: 6 руб. из трех двоек и одной пятерки он не наберет, а `optimal` выдаст 3 x 2 руб.
